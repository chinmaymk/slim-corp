# Project Experts — Spec v0.1

A project-specific "team of experts" for coding agents. Experts are markdown files in the repo, created from the codebase and refined from evidence during normal conversations. An optional single binary (`experts`) gates writes, runs similarity checks, and drives multi-step reasoning loops in which the calling agent supplies the intelligence.

## 1. Constraints

| # | Constraint | Consequence |
|---|---|---|
| C1 | Works with all major coding agents | Plain files + shell; no agent-specific APIs required |
| C2 | No background work | No daemon, cron, CI, hooks, MCP server. Every action happens inside a conversation |
| C3 | Can't assume full system access | Binary is optional; everything degrades to agent-only file edits |
| C4 | Binary never calls an LLM, never touches the network | Judgment is returned to the agent as questions |
| C5 | Learning is user-visible | All writes land in the repo diff; curation only on explicit request |

Non-goals: global/user-level experts, hosted services, auto-commits.

## 2. Terms

- **Expert** — a scoped body of project knowledge (`EXPERT.md`).
- **Rule** — a promoted, durable statement inside an expert.
- **Lesson** — a recorded observation, not yet promoted.
- **Evidence** — a reference that justifies a lesson: `path[:line]`, `commit:<sha>`, `pr:<n>`, or `user`.
- **Decision** — a question the binary needs the agent to answer before it can write.
- **Task** — one step of a multi-step loop (curate, spawn, verify, reflect, init).

## 3. Layout

```
AGENTS.md                      # contains the short "Experts" section (§10.1)
CLAUDE.md / GEMINI.md / ...    # one-line pointers (§10.3)
.experts/
  config.toml                  # settings + schema_version
  PROTOCOL.md                  # full agent procedures (§10.2)
  registry.md                  # derived index of experts (§4.2)
  _inbox.md                    # raw lessons written without the binary (§4.5)
  _unassigned/lessons.md       # lessons with no matching expert
  <expert>/
    EXPERT.md                  # frontmatter + rules
    lessons.md                 # pending lessons
  log.jsonl                    # append-only event log (§4.6)
  .cache/                      # gitignored: scan results, similarity index
```

`.gitattributes` (written by `init`):
```
.experts/log.jsonl            merge=union
.experts/*/lessons.md         merge=union
.experts/_inbox.md            merge=union
```

## 4. File formats

### 4.1 `EXPERT.md`

```markdown
---
name: billing-ledger              # kebab-case, unique, == directory name
summary: Ledger writes, refunds, invoice lifecycle, Stripe sync.
scope: ["src/billing/**", "migrations/*ledger*"]
triggers: [refund, invoice, idempotency, ledger]
budget_tokens: 1500               # soft cap for the body
created: 2026-10-11
updated: 2026-10-11
status: active                    # active | retired
---

## Invariants
- [R-4c1e9a] Ledger rows are append-only; corrections are new reversing rows. <!-- c=4 v=2026-10-11 src=L-7f3a2c,L-91b0de -->

## Conventions
- [R-0d22b7] Money is integer minor units (`amount_cents`), never floats. <!-- c=2 v=2026-10-02 src=L-1a2b3c -->

## Pitfalls
- [R-e8f415] Stripe webhooks can arrive before the API call returns; handlers must upsert. <!-- c=1 v=2026-10-11 src=L-5e6f70 -->

## Decisions
- [R-33aa01] Chose Postgres advisory locks over Redis locks for refunds (no Redis in prod). <!-- c=1 v=2026-09-30 src=pr:212 -->
```

- Sections are fixed: `Invariants`, `Conventions`, `Pitfalls`, `Decisions`. Empty sections may be omitted.
- Rule line grammar: `- [R-<6hex>] <text> <!-- c=<int> v=<YYYY-MM-DD> src=<ref>[,<ref>...] -->`
  - `c` = confirmation count, `v` = last verified date, `src` = lesson IDs or evidence refs.
  - The HTML comment is invisible in rendered markdown; agents may ignore it when reading.
- IDs are `R-` + first 6 hex of `sha256(expert + text + created_ts)`. Hash IDs avoid collisions across branches.

### 4.2 `registry.md` (derived)

Regenerated by `experts index` (and after any write that changes frontmatter). Agents without the binary update it by hand.

```markdown
<!-- generated by experts; source of truth is each EXPERT.md frontmatter -->
| expert | scope | triggers | summary |
|---|---|---|---|
| billing-ledger | src/billing/**, migrations/*ledger* | refund, invoice, idempotency, ledger | Ledger writes, refunds, invoice lifecycle, Stripe sync. |
```

`experts check` reports drift between registry and frontmatter.

### 4.3 `lessons.md`

One block per lesson, separated by a blank line:

```markdown
### L-7f3a2c
when: 2026-10-11T14:02:10Z
text: Refund calls must pass idempotency_key derived from refund_id.
evidence: src/billing/refund.ts:42, user
kind: correction            # correction | failure | discovery | instruction | reflection
confirmations: 2
agent: claude-code          # free-form, optional
status: open                # open | promoted | merged | discarded
```

Promoted, merged, or discarded lessons are removed from `lessons.md` during curate (history stays in `log.jsonl`).

### 4.4 `config.toml`

```toml
schema_version = 1

[budgets]
expert_tokens = 1500        # default per-expert body cap
lessons_per_expert = 30     # above this, route emits a curate nudge
inbox_max = 20

[similarity]
engine = "lexical"          # lexical | static-embed (v2)
duplicate = 0.85            # >= : treat as confirmation
related = 0.55              # >= : ask the agent (needs_decision)

[promotion]
min_confirmations = 2       # lessons at/above this are promote-ready
stale_days = 180            # rules not verified within this are verify candidates

[spawn]
min_cluster = 3             # unassigned/off-scope lessons needed to propose a new expert
```

### 4.5 `_inbox.md` (no-binary fallback)

Same block format as §4.3 but `L-` ID may be omitted and `expert:` may be added as a hint. `experts ingest` (and implicitly any write command) runs inbox lessons through `record` and empties the file.

### 4.6 `log.jsonl`

One JSON object per line, append-only, never rewritten.

```json
{"v":1,"ts":"2026-10-11T14:02:10Z","ev":"lesson.recorded","id":"L-7f3a2c","expert":"billing-ledger","text":"...","evidence":["src/billing/refund.ts:42","user"],"kind":"correction","agent":"claude-code"}
{"v":1,"ts":"...","ev":"decision.opened","id":"D-1c9e0f","type":"similar","subject":"L-7f3a2c","candidates":[{"id":"L-42aa10","score":0.71}],"options":["merge","supersede","keep-both","discard"]}
{"v":1,"ts":"...","ev":"decision.resolved","id":"D-1c9e0f","choice":"merge","target":"L-42aa10","note":"same rule"}
```

Event types:

| ev | meaning |
|---|---|
| `lesson.recorded` / `lesson.confirmed` / `lesson.discarded` | lesson lifecycle |
| `rule.promoted` / `rule.edited` / `rule.verified` / `rule.retired` | rule lifecycle |
| `expert.created` / `expert.split` / `expert.merged` / `expert.retired` / `expert.scope_changed` | expert lifecycle |
| `decision.opened` / `decision.resolved` / `decision.expired` | pending questions |
| `loop.started` / `loop.step` / `loop.finished` / `loop.aborted` | multi-step loops |
| `route` | which experts were loaded for a task (optional; `--log`) |

Open decisions and loop state are derived from the log. The binary is stateless between calls.

## 5. CLI

### 5.1 Conventions

- Invocation: `experts <command> [args] [--json] [--root <dir>]`. Root defaults to the nearest ancestor containing `.experts/`.
- Output: default is `key: value` lines (stable, easy for any agent to read). `--json` emits one JSON object.
- Every response has `status:`. Every non-terminal response has `next:` with the exact command(s) to run.
- Exit codes: `0` ok/done, `10` needs_decision, `11` task (loop continues), `2` usage error, `3` validation error, `4` lock timeout.
- Writes are atomic (write temp + rename) under `.experts/.lock` (flock; 5s timeout; no long-lived holder).
- The binary only reads/writes inside the repo root. It reads source files only to validate evidence and for `scan`/`verify` context.

### 5.2 Statuses

| status | meaning | agent action |
|---|---|---|
| `ok` | write or query done | continue |
| `confirmed` | lesson matched an existing one; its count incremented | continue |
| `needs_decision` | judgment needed | answer with `experts resolve` |
| `task` | loop step for the agent to perform | do the work, submit with `experts resolve` |
| `done` | loop finished | report summary to user |
| `rejected` | invalid input (e.g., evidence path missing) | fix and retry, or drop |

### 5.3 Commands

#### `experts init [--scan]`
Creates `.experts/`, `config.toml`, `PROTOCOL.md`, `.gitattributes` entries, the AGENTS.md section, and pointer files. With `--scan`, starts the **init loop** (§6.1). Idempotent; never overwrites existing experts.

#### `experts scan [--since <date>] [--max-commits N]`
Deterministic repo survey; writes `.experts/.cache/scan.json`, prints a summary.
- Manifests/frameworks detected (package.json, go.mod, Cargo.toml, pyproject, etc.).
- Directory boundaries (top-level and package roots).
- Co-change clusters from `git log --name-only` (Jaccard on commit sets, threshold 0.3).
- Hotspots (churn × recency).
- Requires `git` on PATH for history; skips history otherwise.

#### `experts route [--files <paths...>] [--task "<text>"] [--log]`
```
status: ok
experts: billing-ledger, api-auth
load: .experts/billing-ledger/EXPERT.md, .experts/api-auth/EXPERT.md
why: billing-ledger=scope(src/billing/refund.ts)+trigger(refund); api-auth=scope(src/api/middleware.ts)
nudge: billing-ledger has 34 open lessons (cap 30) — suggest `experts curate` to the user
```
Scoring: scope match = 1.0 per file (max), trigger match = 0.5 per term, co-change neighbor = 0.3. Return those ≥ 0.5, max 3 by default (`--max`). Nudges are informational and never acted on without the user.

#### `experts record "<text>" --evidence <ref>[,<ref>...] [--kind <k>] [--expert <name>] [--agent <name>]`
Pipeline:
1. **Validate evidence**: paths exist (line within range), commits resolve (`git cat-file`), `user` always valid. Any invalid evidence → `rejected`.
2. **Assign expert**: `--expert` if given, else route evidence paths + text. No match → `_unassigned`.
3. **Similarity** against that expert's open lessons and rules, plus `_unassigned`:
   - best ≥ `duplicate` → increment confirmations → `confirmed`.
   - best ≥ `related` → open decision → `needs_decision`.
   - else → append → `ok`.
4. After write: if any lesson reaches `min_confirmations`, add `next:` hint about curate (not a command to run unprompted).

```
status: needs_decision
decision: D-1c9e0f
subject: L-7f3a2c "Refund calls must pass idempotency_key derived from refund_id."
similar: L-42aa10 (0.71) "Refunds require an idempotency key."
similar: R-0d22b7 (0.58) "Money is integer minor units ..."
ask: Same rule, refinement, or conflict?
options: merge:<id> | supersede:<id> | keep-both | discard
next: experts resolve D-1c9e0f <option> [--text "<merged text>"] [--note "<why>"]
```

#### `experts resolve <D-id|T-id> <option> [--text "..."] [--note "..."] [--file <path>]`
Answers a decision or submits a task result. `--file` passes structured results (JSON or markdown) for loop steps. Returns the next state (`ok`, `needs_decision`, `task`, `done`).

#### `experts pending`
Lists open decisions and in-progress loops. Decisions older than 14 days → `decision.expired`, the subject lesson stays `open`.

#### `experts check [--fix]`
Deterministic integrity report:
- frontmatter schema, name/dir mismatch, unknown sections, malformed rule lines
- scope globs matching zero files
- rule/lesson evidence paths that no longer exist
- body over `budget_tokens` (tokens ≈ chars/4)
- open lessons over cap, inbox over cap
- overlapping scopes (same file in >2 experts)
- registry drift
- rules with `v` older than `stale_days`

`--fix` applies only mechanical fixes (regenerate registry, normalize formatting). Never changes meaning.

#### `experts index`
Regenerates `registry.md`.

#### `experts ingest`
Processes `_inbox.md` through `record`. May yield decisions.

#### `experts stats`
Per expert: rules, open lessons, promote-ready, stale rules, last updated, route hits (if `--log` used).

#### Loops: `experts curate | spawn | verify | reflect [--expert <name>] [--max-steps N]`
See §6.

## 6. Loop protocol

A loop is a sequence of **tasks** handed to the agent one at a time. The binary plans and validates; the agent reasons and writes text.

Task response shape:
```
status: task
task: T-8b21c4
loop: curate/billing-ledger (step 2/5)
kind: summarize-cluster
ask: These 3 lessons describe one rule. Write a single rule (<= 25 words) and choose a section.
context: L-7f3a2c "...", L-42aa10 "...", L-91b0de "..."
read: src/billing/refund.ts:30-60            # optional files the agent should open
respond: experts resolve T-8b21c4 promote --text "<rule>" --section Invariants
alt: experts resolve T-8b21c4 skip --note "<why>"
```

Rules:
- Each task is self-contained (agent needs no memory of earlier steps).
- `--max-steps` (default 10) bounds a single call chain; the loop resumes with the same command.
- `experts <loop> --abort` ends it; partial results already written stay.
- The binary validates every submission (length, section name, IDs exist, budget) and re-asks on failure with the reason.
- At `done`, the binary prints a change summary for the agent to show the user.

### 6.1 `init --scan`
1. `scan` runs.
2. Task `propose-experts`: given scan summary, propose 3–7 experts as JSON `[{name, summary, scope, triggers}]`.
3. Binary validates globs (non-empty, overlap report) → task `confirm-with-user`: agent shows proposal, submits user's edits.
4. Binary writes `EXPERT.md` skeletons and registry.
5. Per expert, task `seed-rules`: read listed files/docs, propose ≤ 5 rules with evidence. Each goes through `record` (so seeds start as lessons, not rules, unless the user explicitly confirms).

### 6.2 `curate`
Order of work:
1. **Ingest** inbox.
2. **Cluster** open lessons per expert (similarity ≥ `related`, single-link).
3. For each cluster with total confirmations ≥ `min_confirmations` → task `summarize-cluster` → promote rule.
4. For conflicting pairs (opened decisions of type `conflict`) → task `resolve-conflict`.
5. If expert over budget → task `compress-expert` (rewrite body within budget, must keep all rule IDs or explicitly retire them).
6. If `_unassigned` or off-scope lessons form a cluster ≥ `min_cluster` → hand off to `spawn`.
7. If two experts' scope overlap > 50% and rule similarity high → task `merge-experts?` (agent may decline).
8. If an expert > 2× budget after compression → task `split-expert` (propose partition of rules + scopes).
9. Summary.

### 6.3 `spawn`
Task `define-expert` with the cluster lessons and evidence paths → agent returns `{name, summary, scope, triggers}` → binary validates, creates expert, moves lessons.

### 6.4 `verify [--expert X] [--rule R-...]`
Picks stale rules (oldest `v` first, or those whose evidence paths changed since `v` per git). Task `verify-rule`: read listed files, answer `holds | changed --text "<new>" | obsolete`. Updates `v`, edits, or retires.

### 6.5 `reflect --files <touched...> [--task "<text>"]`
End-of-task. Binary routes the touched files and asks 1–3 targeted questions, e.g.:
- "You edited `src/billing/refund.ts`; billing-ledger has no rule about X. Did anything surprise you?"
- "Rule R-e8f415 covers this file. Did it hold?" (`holds` → bumps `c`/`v`)

Answers flow through `record`. Empty answers are fine and expected.

## 7. Similarity

### v1: lexical (no model)
- Normalize: lowercase, strip punctuation, split camel/snake case, drop a small stopword list, light stemming.
- Score = `0.6 × BM25 (normalized to 0–1 over the candidate set) + 0.4 × Jaccard of word 3-shingles`.
- Code identifiers (backticked or matching `[A-Za-z_][A-Za-z0-9_]*\.[A-Za-z_]` etc.) get 2× weight: shared identifiers are strong signals.
- Index built on demand into `.experts/.cache/`; rebuilt if any source mtime is newer.

### v2: static embeddings (optional)
- Embedded static token-embedding model (≈10–30 MB, model2vec-style), mean-pooled, cosine.
- Score = `max(lexical, embed)` for duplicate detection; `embed` alone for clustering.
- Thresholds stay in config; `experts calibrate` (v2) prints score distributions so a project can tune them.

Similarity only nominates. Any outcome other than exact/near-exact duplicate becomes a decision for the agent.

## 8. Lifecycle rules

- Lesson → rule only through curate (`summarize-cluster`) or explicit user instruction (`experts resolve ... promote`).
- A rule's `c` increments on `confirmed` lessons and `verify: holds`.
- Rules are never deleted silently; `retired` rules are removed from `EXPERT.md` and logged.
- Expert `status: retired` keeps the directory with an empty body for one curate cycle, then is removed.
- Hard caps (lessons, inbox) never block `record`; they only trigger nudges.

## 9. Without the binary

Agents follow `PROTOCOL.md` manually:
- **route**: read `registry.md`, match globs/triggers by judgment.
- **record**: append a block to `_inbox.md` (never edit `EXPERT.md` directly unless the user asks).
- **curate**: on user request, do §6.2 by hand; regenerate `registry.md`.
When the binary is later available, `experts ingest` normalizes everything.

## 10. Agent integration

### 10.1 `AGENTS.md` section (always loaded, ≤ 15 lines)
```markdown
## Experts
This repo keeps project knowledge in `.experts/`. Procedures: `.experts/PROTOCOL.md`.
- Before a task: `experts route --files <paths> --task "<summary>"` and read the listed files.
  (No `experts` binary? Read `.experts/registry.md` and pick matching experts.)
- When the user corrects you, an approach fails for a non-obvious reason, or you find an
  undocumented rule: `experts record "<one-line rule>" --evidence <path:line|commit:sha|user>`.
  (No binary? Append to `.experts/_inbox.md`.)
- If a command returns `needs_decision` or `task`, handle it before continuing.
- After a task: `experts reflect --files <touched>` and answer briefly.
- Run `experts curate|spawn|verify` only when the user asks. Mention nudges in one line.
```

### 10.2 `PROTOCOL.md`
Full procedures (§5–§9) written for agents, including no-binary steps. Shipped by `init`, versioned with `schema_version`.

### 10.3 Pointers
| Agent | File | Content |
|---|---|---|
| Codex, Cursor, Copilot, Amp, Jules, others | `AGENTS.md` | native |
| Claude Code | `CLAUDE.md` | `@AGENTS.md` |
| Gemini CLI | `GEMINI.md` | `See AGENTS.md.` (or set `contextFileName` to `AGENTS.md`) |
| Cursor (older) | `.cursor/rules/experts.mdc` | `alwaysApply: true`, points to AGENTS.md |
| Windsurf | `.windsurf/rules/experts.md` | pointer |
| Cline | `.clinerules/experts.md` | pointer |
| Agents with skills | `.claude/skills/experts/SKILL.md` (and equivalents) | PROTOCOL.md content for on-demand loading |

`init` writes only pointers that don't already exist and appends (never replaces) the AGENTS.md section between `<!-- experts:begin -->` / `<!-- experts:end -->` markers.

## 11. Distribution

- Single static binary, Go (simplest cross-compile) — linux/darwin/windows × amd64/arm64.
- No runtime deps; `git` optional (history features disabled without it).
- Install: download release asset, or `go install`. Optionally vendored at `.experts/bin/` per repo (gitignored by default).
- `experts version` prints binary version and supported `schema_version` range; refuses to write to a newer schema.
