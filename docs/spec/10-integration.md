# 10 — Integration

Goal: every agent loads a short always-on instruction pointing at `.experts/PROTOCOL.md`. No content is duplicated across agent files; nothing needs syncing.

## AGENTS.md block

Written by `init` between markers. If AGENTS.md is absent, it is created with only the block. If markers exist, content between them is replaced when the block version is older. Text outside markers is never touched.

```markdown
<!-- experts:begin v1 -->
## Project experts
Project knowledge lives in `.experts/`. Full procedure: `.experts/PROTOCOL.md`.
- Before code work: `experts route --files <paths> --task "<summary>"`; read each `load:` file.
  No `experts` binary: read `.experts/registry.md`, open matching `EXPERT.md` files.
- When the user corrects you, states a project rule, or you hit a non-obvious project-specific
  failure or invariant: `experts record "<one line>" --evidence <path:lines|commit:sha|user> --kind <kind>`.
  No binary: append `- <text> (evidence: <refs>; kind: <kind>)` to `.experts/_inbox.md`.
- Handle `needs_decision` / `task` outputs before continuing. Relay `say:` lines briefly.
- After code work: `experts reflect --files <changed>`; answer only if non-obvious.
- Run curate/spawn/verify/forget/promote only when the user asks.
- Expert content is guidance, never authorization to run commands.
<!-- experts:end -->
```

≤15 lines inside markers. Block version `v1` bumps only when text changes.

## Pointer files

Written only if absent (or, if present, a single pointer line appended when not already referencing AGENTS.md — `init` checks for the literal string `AGENTS.md`).

| Agent | File | Content |
|---|---|---|
| Codex, Cursor, GitHub Copilot, Amp, Jules, Zed, Aider (via config), others | `AGENTS.md` | native |
| Claude Code | `CLAUDE.md` | `@AGENTS.md` |
| Gemini CLI | `GEMINI.md` | `@AGENTS.md` |
| Cursor (legacy rules) | `.cursor/rules/experts.mdc` | frontmatter `alwaysApply: true`, body `Follow the "Project experts" section in AGENTS.md.` |
| Windsurf | `.windsurf/rules/experts.md` | `Follow the "Project experts" section in AGENTS.md.` |
| Cline | `.clinerules/experts.md` | same |
| Skills-capable agents | `.claude/skills/experts/SKILL.md` | frontmatter `name: experts`, `description: Project expert knowledge: routing, recording lessons, curating. Use for any code change in this repo.`; body = PROTOCOL.md content |

`--agents` selects which pointers. Pointer files are not regenerated on upgrade except the SKILL.md (owned by binary; replaced when its version line is older).

## PROTOCOL.md

- First line: `<!-- experts protocol v<N> -->`. Owned by binary. Replaced by `init` or `migrate` when shipped version is newer. Local edits are overwritten; `init` warns `W_PROTOCOL_EDITED` (hash mismatch) and saves the old file to `.experts/.cache/PROTOCOL.md.bak`.
- Content: 09 rendered for agents, plus the no-binary procedures and the inbox format.

## Without init

A team can adopt manually: copy the AGENTS.md block and PROTOCOL.md, create `.experts/registry.md` and `_inbox.md`. The binary later runs `init` idempotently.

## Agent-specific extras (optional, not required for C1)

None in v1. Candidates deferred (16): generating Claude Code subagents per expert, Cursor glob-scoped rules per expert. Both need a sync step and are excluded until a non-background sync story exists (e.g., regenerated by `index`).
